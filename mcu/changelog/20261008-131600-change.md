# Change: Fix Speed Calculation and Timing Logic

- **Date and time:** 2026-10-08 13:16:00
- **Change summary:** Replaced flawed velocity formula and continuous millisecond polling with microsecond timing and a two-stage edge detection state machine.
- **Files modified:**
  - `src/impl/main.hpp`
- **Description of the changes:**
  - Converted time tracking from `millis()` to `micros()` to provide adequate timing resolution for sensors spaced 1 cm apart.
  - Implemented `GateState` (`WAITING_FOR_SENSOR1`, `WAITING_FOR_SENSOR2`) to ensure timestamps are registered on the first entry edge and not overwritten continuously while the sensor is covered.
  - Corrected velocity formula to `(distanceCm * 1,000,000.0f) / elapsedUs` instead of dividing and adding 1000.
  - Added timeout handling (3 seconds) to reset the state machine if an object triggers sensor 1 but never reaches sensor 2.
  - Only prints when a measurement event completes or times out rather than flooding the serial console every loop iteration.
- **JUSTIFICATION FOR THE CHANGES:**
  The original code suffered from:
  1. An erroneous arithmetic formula adding 1000 instead of scaling milliseconds to seconds.
  2. Insufficient resolution using `millis()`, causing division by 1 or 0 for short sensor intervals.
  3. Continuous re-reading without latching edges, leading to zero elapsed time calculations and constant outputs of ~999/1000.
