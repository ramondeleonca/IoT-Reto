# Change: Reject Invalid Time-of-Flight Readings

- **Date and time:** 2026-10-11 19:21:55
- **Change summary:** Prevent failed VL53L0X measurements from being printed as distances.
- **Files modified:**
  - `src/impl/tof.hpp`
  - `changelog/changelog.md`
- **Description of the changes:**
  - Wait for each sensor to boot after releasing its shutdown pin.
  - Initialize each ranging result before asking the sensor to populate it.
  - Return the distance only when the ranging call succeeds and the sensor reports a valid range status.
  - Return `-1` for failed or invalid readings, using the existing invalid-distance output convention.
- **JUSTIFICATION FOR THE CHANGES:**
  The sensors were queried immediately after being released from shutdown, before their boot time was guaranteed. The sensor API also reports measurement failures separately from the range data. Ignoring that status and reading an uninitialized result allowed failed measurements to be printed as the repeated value `10912.00mm`.
- **The prompt that caused it:**
  "this code is always outputting
  10912.00mm, 10912.00mm
  10912.00mm, 10912.00mm
  10912.00mm, 10912.00mm

  make the most minimal, necessary changes to make this code work and output the real distance"
