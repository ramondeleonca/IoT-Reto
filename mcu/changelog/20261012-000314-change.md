# Change: Latch Sensor Trigger Signal

- **Date and time:** 2026-10-12 00:03:14
- **Change summary:** Activate a software signal when both sensors trigger within the configured window and hold it until reset time.
- **Files modified:**
  - `src/impl/main.hpp`
  - `changelog/changelog.md`
- **Description of the changes:**
  - Detect transitions into the configured sensor range rather than repeatedly polling an already-detected object as a new trigger.
  - Pair sensor timestamps only when their separation is within `triggerWindow`.
  - Expire unmatched timestamps after the trigger window and allow future entries to trigger.
  - Set `active` when both sensors trigger in time, and clear it after `resetTime`.
  - Reduce the additional loop delay from 5 ms to 1 ms.
- **JUSTIFICATION FOR THE CHANGES:**
  The existing code used a 2000 ms timeout to clear trigger timestamps, did not use `triggerWindow` to qualify a paired trigger, and had no latched `active` signal. Timestamping sensor readings in microseconds also prevents a zero-millisecond interval from suppressing velocity calculation.
- **The prompt that caused it:**
  "make the least amount of changes needed to make this code react to sudden changes and not just after every 2000ms, i need it to trigger in the window, after both sensors were triggered inside the window, the signal should stay active until the reset time"
